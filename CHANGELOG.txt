# Ebon Affix Alert Changelog

## v1.1.2

- Fixed issue that kept you from staying afk
  - Added a separate advertised release version so development builds can use a higher local version without falsely advertising an unreleased update to other players.
  - Fixed update-channel packets being rejected as invalid chat escape codes by replacing the `|` protocol delimiter with chat-safe `~`.
  - Added a 1-second retry backoff and 3-attempt limit for failed update-channel sends.
  - Fixed realm update-channel discovery on Project Ebonhold by resolving `ebonaffixalert` directly with GetChannelName before using a tuple-width-agnostic GetChannelList fallback.
  - Added `/eaa updateDebug` to show update-channel resolution, queued sends, actual TX packets and RX packets.
  - Added Update Debug to Interface > AddOns > EbonAffixAlert > Diagnostics.

## v1.1.1 - 2026-08-10

- Fixed existing bag items being re-alerted after unrelated loot by using a stable canonical item identity for ownership snapshots instead of the full rendered item hyperlink.
- Fixed duplicate tracked-item alerts during ordinary bag/equipment updates by debouncing BAG_UPDATE until inventory changes have settled.
- Fixed a Lua 5.1 forward-declaration error in the manual update-result timer.
- Fixed manual Update Check result timing so the up-to-date result is processed by the active realm-update frame after 1 second, independently of the 5-second button cooldown.
- Manual Update Check now reports its result after 1 second while retaining the 5-second anti-spam cooldown.
- Added an Update Check button to Interface > AddOns > EbonAffixAlert with a visible 5-second cooldown to prevent update-channel/chat spam.

- Added realm-wide update tracking over a hidden `ebonaffixalert` chat channel.
- EAA broadcasts/answers semantic version checks and alerts once per session when a newer peer version is seen.
- Added a clickable GitHub Releases chat link; clicking opens a copyable releases URL window for WoW 3.3.5a.
- Added `/eaa update` for update/channel status and `/eaa updateTest` (alias `/eaa realmTest`) for a channel echo self-test.

## v1.1.0 - 2026-08-10

- Generalized the built-in verified Weapon proc signatures so they no longer depend on one source item's damage, healing, duration, rating, or percentage values.
- Removed the remaining legacy Flat UI theme implementation from EbonAffixAlert.lua; only Modern and Fantasy remain.
- Added a built-in verified original Weapon-proc signature table as the primary Weapon-affix identification source.
- Retained Project Ebonhold `ExtractionService.learnedAffixes` description matching as a fallback for future/new Weapon affixes that are not yet in the verified table.
- Added support for original ranged weapon tooltip lines shaped as `Equip: Chance to strike...`.
- Twin Shot remains on the live Ebonhold-description fallback because no verified original Twin Shot source proc has been established yet.
- Added `/eaa weaponAffixes` to export all `weaponOnly` affix names, spell IDs, Ebonhold API descriptions, and normalized comparison text into a copyable window.
- Changed Weapon-affix proc identification to score meaningful word overlap between the item proc and Project Ebonhold's full affix description, allowing matches even when Ebonhold wraps the proc text in instructional wording.
- Improved Weapon-affix proc matching to tolerate small wording differences between Ebonhold spell descriptions and generated item proc text, and expanded Debug output for proc comparison troubleshooting.
- Added short delayed tooltip retries for newly acquired weapons so proc-based Weapon-affix detection remains reliable when item data is not immediately available, such as when taking an item from the mailbox.
- Added Weapon-affix proc detection using Project Ebonhold's affix spell data, allowing normally named weapons to be identified from their "Chance on hit"/"Chance to strike" effects.
- Removed legacy "... of Affix" Weapon-name suffix detection.
- Fixed a Lua scope issue that could cause `FindTrackedWeaponAffixByProc` to be nil when a tracked Weapon-affix item was looted.

## v1.0.1 - 2026-08-09

- Adjusted the General filter controls so "Tracked only" no longer overlaps the "Select All" button.
- Improved the Fantasy affix filter with a brighter, unobscured Filter label, a darker input field, brighter typed text, and a clearer bronze-gold border.
- Renamed "Alert Noise" to "Alert Sound".
- Corrected the Weapon affix name "Frality" to "Frailty".
- Renamed "Select Page" to "Select All".
- Added clickable General rank headers: clicking a Roman numeral tracks all available General affixes of that rank, or clears the rank if every available affix at that rank is already selected.
- Added explanatory tooltips to General rank headers and each affix row's "All" button.
- Removed the extra "EAA tracking: ..." line from Ebonhold-powered affix tooltips.


## v1.0.0 - 2026-08-09

- First public release of Ebon Affix Alert.
- Includes General and Weapon affix tracking, server-driven rank/icon data, loot alerts, Loot History, minimap controls, diagnostics/support tools, and Modern/Fantasy UI styles.
- Added the final styled README.html, MIT LICENSE.txt, and release documentation.
